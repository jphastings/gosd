Part of epic gosd-47z3. Direction from JP (2026-08-11): a crash report
invites its reader to forward the whole file to a support site, so anything
secret that reached the app's console must not survive into the file. Two
mechanisms, both landing here:

1. **Automatic, no app changes.** Scan the report for any string equal to one
   of the app's env var VALUES and replace it with `{$ENV_VAR}`.
2. **Opt-in, for secrets that never came from the environment.**
   `RegisterSecretString(secret, replacement string)` in the public `fault`
   package; occurrences become `{secret: <replacement>}`.

This bean blocks gosd-s9uq and gosd-aa1p deliberately: the console-tail
capture must never ship a path that writes app output to the card
unredacted, so redaction lands before the thing that needs it.

## Why gosd-init is the redactor

It already holds the app's env — it built the slice (`sequence.go`'s `env`,
via `mergeUserEnv`) — and it holds the console tail. `mergeUserEnv`'s
docstring already states the principle this bean generalises: *"Only keys
and their source are ever logged, never values: they may be secrets."*

The serial console stays UNREDACTED. It is a physically-attached debug
channel for someone already holding the board, not a file that travels.
Redaction happens at report-render time, not at capture time.

## LOCKED: only user env is redacted, never the GOSD_* namespace

`GOSD_BOARD`, `GOSD_HOSTNAME` and `GOSD_DATA_FLUSH` are gosd's own, are not
secret, and are catastrophically short: `GOSD_DATA_FLUSH` is `0` or `1`, so
redacting its value would replace every `0` in the technical detail with
`{$GOSD_DATA_FLUSH}` and destroy the log. Redact only the values
`mergeUserEnv` returns — the app's own, from baked config.json and
gosd.toml — which is exactly the set the existing docstring already calls
possible secrets.

## Todos

- [x] An internal redactor package: takes a set of (needle, replacement)
      pairs and a body, returns the redacted body. Pure, table-testable
- [x] **Longest needle first.** Otherwise a secret that contains another
      secret as a substring leaves a mangled fragment of the longer one
- [ ] **A minimum needle length**, below which a value is skipped and the
      skip is logged (key only, never the value). An app with `DEBUG=1` or
      `PORT=80` would otherwise shred the report. Pick a threshold with a
      stated rationale; note it cuts both ways — a genuinely short secret
      goes unredacted, which is why the log line matters
- [ ] Redact the WHOLE rendered body, not only the technical-detail section.
      An app is perfectly capable of interpolating a key into its own
      `Problem` or `Fix` string. Frontmatter is generated by gosd from
      known-safe fields and needs no pass
- [ ] Wire into the renderer (gosd-pun9) so every producer is covered by
      construction, rather than at each call site
- [ ] Tests that assert the negative directly: a report rendered from a
      console tail containing an env value must not contain that value
      anywhere in its bytes

## RegisterSecretString: the registration must outlive the app

The hard part. On a panic the app never gets to hand anything over, so a
secret registered only in the app's memory is exactly the one still in the
tail gosd-init is about to write. The registration therefore has to reach
gosd-init BEFORE the crash.

- [ ] `RegisterSecretString` writes through to a registration file in `/run`
      (tmpfs, already mounted) immediately on call, so gosd-init can redact
      a panic the app never saw coming. Mode 0600; write-`.tmp`-then-rename
      so gosd-init can never read a half-written registration
- [ ] It is idempotent and additive; registering the same secret twice is
      not an error. Bound the number and total size of registrations —
      an app that registers in a loop must not fill tmpfs
- [ ] Off-device (macOS, `go test`, no `/run/gosd`), registrations are held
      in memory and applied to the stderr rendering, so the developer sees
      the same redaction their user will
- [ ] Exported docstring must be explicit that the plaintext secret is
      written to tmpfs. It is RAM, never the card, and the app already holds
      it in RAM on a device with no shell and no interactive surface — but a
      reader deserves to know rather than infer it
- [ ] The `replacement` is a human label, not a secret: render as
      `{secret: stripe-api-key}`. Say so in the docstring, since the
      parameter name alone invites someone to pass a second secret

## Known limitation to document, not fix

The ring buffer truncates from the front, so a secret straddling the
truncation boundary can leave a fragment that matches no needle. Mitigate by
dropping the leading partial line entirely (which the buffer wants to do for
readability anyway) and state the residual risk in the docs rather than
implying redaction is a guarantee.

## Review note

This is a security-relevant negative claim — "secrets do not reach the file"
— so it needs an adversarial pass before JP's review, per CLAUDE.md. The
interesting failure is not a missed replacement but over-redaction making a
report useless, and the short-value threshold is where that lives.
