## Findings

1. **GO/no-go: GO.** The three-package knope.toml works end-to-end. Tags produced: `gosd/vX.Y.Z` + the plain `vX.Y.Z` Go-module tag (from root go.mod), `artifacts/vX.Y.Z`, `npm/gosd/vX.Y.Z` — the latter two exactly match the existing workflow triggers; publish-npm.yml needs no changes.
2. **Change-file frontmatter keys must be UNQUOTED**: `npm/gosd: patch` works; `"npm/gosd": patch` is SILENTLY ignored (no error, no bump). Must be documented prominently in docs/releasing.md; consider a later hardening of change-file-check to grep for quoted keys.
3. **`$changelog`/`$version` are single-package-only** in CreatePullRequest templates (`variables::too_many_packages` error). The release PR uses a static title and body; reviewers read the diff (changelogs + version files) for content.
4. **First-release bootstrap tag required**: with no `gosd/v*` tag in history, `knope release` immediately wants to create a spurious `gosd/v0.6.0` release ("autogenerated body") and re-create the existing plain v0.6.0 tag. With a one-time `git tag gosd/v0.6.0 v0.6.0 && git push origin gosd/v0.6.0` (aligned to whatever the current CLI release is at adoption), it does nothing until a real prepared release exists. This step is now in gosd-9qb0.
5. **The compgen guard in prepare-release.yml is essential, not belt-and-braces**: with zero change files, dry-run proceeds to the commit/push/PR steps (the real run would fail at the empty `git commit`, red-flagging every changeless push to main).
6. **0.x bump semantics confirmed** (major→minor, minor→patch): ordinary features produce PATCH bumps until 1.0. Accepted; `knope prepare-release --override-version` is the escape hatch, to document.
7. **Baseline moved during the spike**: v0.6.0 shipped (PR #278/#279) and UNRELEASED.md was freshly reset — so the planned seed change file (config-tree call-out) is OBSOLETE; adoption starts from a clean slate with go.mod `// v0.6.0`, artifacts 0.10.0, npm 0.3.0.


8. **Post-spike addendum (2026-08-14):** the `note` change type (gosd's extra_changelog_sections) renders a "Notes" changelog/release section correctly but implies a PATCH bump — there is no bump-free change type. Use `note` for call-outs that warrant a release but aren't features/fixes.
