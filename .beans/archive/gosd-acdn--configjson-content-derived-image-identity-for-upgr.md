Phase 1 of the upgrade-path design (bean gosd-inau, docs/design/upgrade-path.md §4). Add a build-identity field to internal/initcfg's config.json: content-derived (digest over the boot payload set), NOT a timestamp, so identical rebuilds compare equal and qemu CI stays deterministic. Consumers: provisioning-snapshot skew detection, and phase-2 self-update's am-I-already-running-this check (sha-based, no semver).

## Summary of Changes

**Digest recipe (`internal/initcfg.ComputeIdentity`, `internal/initcfg/identity.go`):** a SHA-256 over the boot payload set — every file `gosd build` writes to GOSD-BOOT, whether at the FAT root (kernel image, DTB(s), the board's own boot-config file, any USB-gadget overlay, the rendered `gosd.toml` template) or packed into the initramfs archive also shipped there (`/init`, `/app`, everything under `/lib/firmware`) — with `config.json` itself excluded entirely (chicken-and-egg: it's baked into that same initramfs, so its final bytes including `Identity` can't be known until `Identity` is computed). Files are hashed in a fixed order (sorted by path); each contributes an 8-byte-big-endian-length-prefixed path followed by an 8-byte-big-endian-length-prefixed content, so path/content boundaries are never ambiguous. FAT-root files are keyed by their literal boot-partition path (no leading `/`); initramfs members are keyed by their in-archive path prefixed `initramfs:` (e.g. `initramfs:/init`) — disjoint namespaces, so a future reader can re-derive `Identity` from a built image alone (list the GOSD-BOOT root minus config.json, unpack `initramfs.cpio.zst` and list its members minus `/etc/gosd/config.json`).

Consequence of excluding config.json wholesale: `Identity` is blind to whatever config.json carries that appears nowhere else in the payload — in practice, only `DataExpand`. `Board`/`Hostname`/`Wifi`/`Env` are also baked into config.json, but they're baked into the rendered `gosd.toml` template too (a real, hashed FAT-root file), so `--hostname`/`--wifi-ssid`/`--wifi-pass`/`--env` still move `Identity` via `gosd.toml` even though config.json's own copies of those values are invisible to it. This is documented in `ComputeIdentity`'s docstring and pinned by `TestBuildIdentityChangesWithHostnameAndWifiViaGosdToml` and `TestBuildIdentityUnaffectedByDataExpand`.

**Reproducibility finding:** `gosd build`'s own image bytes are NOT fully byte-reproducible today — confirmed by building the same fixture inputs twice and diffing the two `.img` files: go-diskfs's FAT32 formatter stamps directory-entry timestamps and a volume serial number from wall-clock time (~26 bytes differ across a 285MB image, confined to exactly those fields; no other non-determinism found). This is hashed around by construction rather than special-cased: `internal/pipeline.Assemble` computes `Identity` from each file's raw bytes *before* they reach the FAT/initramfs-packing layer, never from the finished `.img` or the packed `initramfs.cpio.zst`, so the non-reproducible FAT metadata never enters the digest. `TestBuildIdentityIsReproducibleAcrossRebuilds` (`cmd/gosd/build_integration_test.go`) asserts two independent builds from identical inputs produce identical `config.json` identities. This finding and the exclusion are documented in code comments (`internal/initcfg/identity.go`'s docstring, `internal/pipeline/pipeline.go` above the `ComputeIdentity` call) rather than in `docs/design/upgrade-path.md`, which stays as JP locked it.

**Runtime surface:** `initcfg.Config` gained `Identity string` (`json:"identity,omitempty"`, optional — absent on every pre-existing config.json, parses without error) and a `ShortIdentity()` accessor (first 12 hex chars, for logging) — field + accessor only, no consumer logic yet, per the design's "small prerequisite" framing. `cmd/gosd-init/internal/boot/sequence.go`'s `Run` logs `[gosd] image identity: <short digest>` right after reading config.json when `Identity` is non-empty; a pre-gosd-acdn image (empty `Identity`) logs nothing and boots exactly as before.

**Where it's computed:** `internal/pipeline.Assemble` reads every payload input into memory once (kernel/DTB/board-config/`gosd.toml`/`init`/`app`/firmware/extra-executables), computes `Identity` over all of it except config.json, marshals the final config.json (with `Identity` populated), then builds the initramfs and writes the image exactly once each — no double-build. (`Board.BootFiles` requires a non-nil `Initramfs` reader before the real archive can exist; an empty placeholder `*bytes.Buffer` stands in for that one call, and its own identity — not its content — is what finds the map key to overwrite with the real archive afterward.)

**Tests added:** `internal/initcfg/identity_test.go` (`ComputeIdentity` order-independence, determinism, content/path sensitivity, length-prefix collision-avoidance, empty-set stability, `InitramfsPayloadPath`); `internal/initcfg/config_test.go` gained identity-present/identity-absent `ParseConfig` cases and `TestConfigShortIdentity`; `cmd/gosd/build_integration_test.go` gained `TestBuildBakesImageIdentityIntoConfigJSON`, `TestBuildIdentityIsReproducibleAcrossRebuilds`, `TestBuildIdentityChangesWithBootPayloadContent`, `TestBuildIdentityChangesWithHostnameAndWifiViaGosdToml`, `TestBuildIdentityUnaffectedByDataExpand`; `cmd/gosd-init/internal/boot/sequence_test.go` gained `TestRunLogsImageIdentityWhenPresent` and `TestRunDoesNotLogImageIdentityWhenAbsent`.
