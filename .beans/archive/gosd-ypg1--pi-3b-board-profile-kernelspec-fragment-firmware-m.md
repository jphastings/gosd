First PR of epic gosd-xhc3: everything `gosd build --board=pi-3b
--artifacts-dir` and `gosd build-kernel --board pi-3b` need, without any real
kernel build or artifacts-release coupling. Mirrors how rock-4se's first PR
(#88, gosd-iosp+gosd-0vvh) landed board.go + templates + RegisterInternal +
kernelspec together — `gosd build-kernel` resolves boards through the
registry, so the kernel bean (gosd-0nl7) is unbuildable until this lands
(CLAUDE.md's registration-before-kernel coupling).

## Scope

- `build/boards/pi-3b/`: `manifest.json` (GPU boot firmware at
  raspberrypi/firmware 1.20260521 / 09267f53; WiFi 43430 Cypress blob set at
  RPi-Distro/firmware-nonfree 9794282e with the three
  `raspberrypi,3-model-b` aliases — hashes independently re-verified, see the
  epic's Verified facts), `manifest.go` + `kernelfragment.go` embed packages,
  `kernel.fragment`, `README.md`, `.gitignore`. NO `kernel.config` yet — that
  is generated by gosd-0nl7's real build, with provenance (pi-zero-w precedent:
  gosd-s7fk committed it only after a green local Docker build).
- `kernel.fragment`: pi-zero-2w's trim as the base, minus the dwc2/configfs
  gadget block (no gadget on this board — a dwc2 UDC can never appear behind
  the hard-wired hub), plus the Ethernet/USB-host block
  (USB_DWCOTG/USB_NET_DRIVERS/USB_USBNET/USB_NET_SMSC95XX =y) and
  `CONFIG_SERIAL_8250_RUNTIME_UARTS=1` (gosd-md4w; =1 lines are carried by the
  fragment but not RequiredY — the derivation regex only collects literal =y
  lines, which is correct here).
- `internal/boards/pi3b/`: board.go + templates (config.txt/cmdline.txt per
  the epic's locked template content, no UsbGadget branch;
  `UsbGadgetSupport{Supported: false}` with an actionable reason) +
  board_test.go + templates tests, mirroring pizerow's shape. Artifacts() =
  kernel8.img + bcm2710-rpi-3-b.dtb (URL-less, artifact-release-resolved) +
  manifest boot/WiFi files; RawWrites nil; FirmwareFiles flattens the three
  aliases into brcm/ as literal duplicates.
- `internal/kernelspec`: pi-3b entry (piZeroCommitRef, bcm2711_defconfig,
  arm64 toolchain, DTB dtbs → arch/arm64/boot/dts/broadcom/bcm2710-rpi-3-b.dtb,
  kernel8.img, RequiredY derived from the fragment) + kernelspec_test.go list
  updates (allBoardIDs, boardsByID map, TestPiRequiredYIsDerivedFromFragment
  cases; the Rockchip DTS-patch allowlist is untouched — pi-3b has no patches).
- `cmd/gosd/build.go`: `boards.RegisterInternal(pi3b.New())` with the
  flip-to-Register condition commented (gated on gosd-7wv9's activation).
- `cmd/gosd/build_integration_test.go`: fake-artifacts acceptance test for
  --board=pi-3b (boot partition contents incl. DTB, cmdline gosd.board=pi-3b,
  config.txt arm_64bit=1 + kernel=kernel8.img, initramfs firmware aliases,
  --usb-gadget refusal) + new fake `bcm2710-rpi-3-b.dtb`; update the
  no---board all-boards test and internal-only comments to cover pi-3b's
  exclusion alongside qemu-virt; a --catalog-on-pi-3b-only-writes-nothing test
  (the pre-activation gosd-wskc pattern).
- `docs/board-build-tags.md`: pi-3b / gosd_pi_3b row + internal-only note.

## Locked decisions

- Register via `RegisterInternal` until the activation bean (gosd-wskc /
  gosd-0vvh precedent — public registration would 404 on artifact fetch and
  break CI's image-smoke job).
- No `internal/artifacts.Version`, catalog, CLAUDE.md board-ID, README, or
  COMPATIBILITY.md changes here — all deferred to gosd-7wv9's activation PR
  (rock-4se precedent: gosd-0vvh explicitly deferred the COMPATIBILITY column
  to gosd-h8a8; a deviation from the "column in the first PR" phrasing older
  Pi beans used, justified because an internal-only board has no user-visible
  status to record).
- No build-artifacts.yml changes here — the CI kernel job belongs to
  gosd-0nl7 with the real build.
